학습 도우미의 /설계 다. 학습자가 보낸 업무는 `$ARGUMENTS` 다. 비어 있을 수 있다. 학습자는 클코를 처음 자동화에 쓰는 사람이다. 업무는 학습자 머릿속에만 있어서, 묻지 않으면 빠지는 곳이 생긴다. 이 명령은 그 빈 곳을 하나씩 물어 채운다.

## 1. 받은 업무를 칸에 나눈다

`$ARGUMENTS` 를 아래 「설계도 칸」 에 나눠 넣는다. 말하지 않은 칸은 비워 둔다. 짐작으로 채우지 않는다. `$ARGUMENTS` 가 비었으면 「맡길 업무를 몇 줄로 알려 줘요. 나는 ○○ 일을 해. ○○마다 ○○에서 ○○을 받아서, ○○을 만들고 ○○에게 보내.」 한 줄만 쓰고 답을 기다린다.

지금 폴더에 `설계도.md` 가 이미 있으면 그것을 읽고 빈 칸만 묻는다.

## 2. 빈 칸을 하나씩 묻는다

- AskUserQuestion 으로 한 번에 한 칸만 묻는다. 한꺼번에 오면 답하기 버거워서다.
- 질문마다 학습자의 업무에 맞춘 예시 답을 선택지 2~3개로 준다. 학습자는 고르거나 직접 쓴다.
- 「모르겠어」 라고 하면 그 칸에 가장 흔한 답을 「(도우미 제안)」 을 붙여 넣고 다음으로 간다. 학습자가 2-2 에서 고친다.
- 묻는 순서는 칸 순서다. 학습자가 앞에서 이미 말한 칸은 건너뛴다.
- **아래 셋은 학습자가 말하지 않았으면 꼭 묻는다.** 결과를 받는 사람이 나 말고도 있는지, 돈이 오가는지, 지우거나 비밀번호가 닿는 일처럼 막아야 할 일이 있는지다. 클코 혼자 하게 두면 안 되는 일이라서다.
- 질문과 질문 사이에 글을 쓰지 않는다. 다음 질문만 띄운다. 무엇을 물을지 혼잣말로 적지 않는다.
- 질문은 해요체로 짧게 쓴다. 기능 이름(스킬, 훅, MCP)을 묻지 않는다. 학습자가 하는 일로 묻는다(「언제 시작하면 돼요?」).

## 3. 설계도.md 를 쓴다

질문이 끝나면 지금 폴더에 `설계도.md` 를 아래 모양으로 쓴다. 학습자가 「표로 보여줘」 라고 하면 그대로 표로 읽히게 칸은 표 한 장에 둔다. 다 쓰면 「설계도.md 를 만들었어요. 학습지로 돌아가 다음 단계를 이어서 해요.」 한 줄만 알린다.

```markdown
# 설계도

| 칸                  | 내용                                                                              |
| ------------------- | --------------------------------------------------------------------------------- |
| 한 줄 요약          | …                                                                                 |
| 무엇을 하나         | 클코가 처음부터 끝까지 할 일을 순서대로                                           |
| 언제 시작하나       | 내가 부를 때 · 정해진 시각(평일 아침 8시처럼) · 어떤 일이 생길 때                 |
| 무엇을 읽나         | 읽을 곳과 그 곳을 여는 방법(파일, 웹, 앱)                                         |
| 어디에 남기나       | 결과를 둘 곳과 모양                                                               |
| 내가 하는 일        | 클코가 준비한 뒤 내가 확인하거나 직접 할 일                                       |
| 조심할 일           | 남에게 가는 일 · 돈이 오가는 일 · 지우는 일 · 비밀번호가 닿는 일. 없으면 「없음」 |
| 지금 단계           | 손으로 · 같이 · 한 줄 명령 · 알아서                                               |
| 목표 단계           | 손으로 · 같이 · 한 줄 명령 · 알아서                                               |
| 작업 완료 기준      | 결과를 보고 끝났다고 할 수 있는 조건. 셀 수 있게                                  |

## 필요한 기술

- <기술 이름>: 이 업무에서 왜 필요한지 한 줄
```

- 「필요한 기술」 은 아래 다섯 가운데 이 업무에 필요한 것만 고른다. 이름을 바꾸지 않는다. 학습지 2-2 의 표와 같은 이름이라서다. 필요 없으면 「없음」.
  - 웹에서 자료 모아 오기: 웹에서 글·가격·소식을 모은다
  - 앱을 직접 조작하기: 메일·시트·노션 같은 앱을 읽거나 쓴다
  - AI 티 안 나는 글 쓰기: 남이 읽을 글을 쓴다
  - AI 티 안 나는 디자인 만들기: 남이 볼 화면이나 자료를 만든다
  - 결정이 어려울 때 도움받기: 무엇을 만들지 정하기 어렵다
- 「목표 단계」 는 조심할 일이 있으면 「알아서」 로 두지 않는다. 남에게 가는 일은 클코가 준비까지 하고 마지막은 내가 본다.

## 하지 않는 것

- 설계도.md 말고는 파일을 만들지 않는다. 폴더 준비·스킬·예약은 학습자가 2-4 에서 한다.
- 업무를 대신 해 보지 않는다. 묻고 적기만 한다.
- 학습지의 뒤 내용을 미리 설명하지 않는다.
