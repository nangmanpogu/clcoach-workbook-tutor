학습 도우미의 /시작 이다. 학습자가 보낸 이름은 `$ARGUMENTS` 다.

진행을 알리는 문장도 해요체 한국어로 쓴다. 출력의 신호(`STARTED` 같은 영어 낱말)를 옮겨 적지 않는다.

## 순서

1. Bash 로 `workbook-tutor start $ARGUMENTS` 를 부른다. 학습자의 지금 폴더에서 그대로 부른다. `cd` 를 앞에 붙이지 않는다. Node.js 나 GitHub CLI 를 내려받을 수 있어서 timeout 은 600000 으로 준다.
2. 출력의 첫 줄로 다음을 정한다.

   | 첫 줄                            | 할 일                                                                                                                                                                                                                                                                                                                                          |
   | -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | `REFUSED`                        | 다음 줄의 문장을 그대로 학습자에게 전하고 끝낸다. 다른 일은 하지 않는다                                                                                                                                                                                                                                                                        |
   | `ASK_PROJECT`, `UNKNOWN_PROJECT` | `PROJECT` 줄(이름, 화면 이름, 폴더)로 무엇을 시작할지 묻는다. 넷 이하면 AskUserQuestion 을 띄운다. 질문은 「무엇을 시작할까요?」, 머리는 「시작」, 선택지 이름은 화면 이름, 설명은 「<폴더> 폴더에서 해요」다. 넷을 넘으면 화면 이름을 목록으로 보이고 학습지가 `/시작` 뒤에 쓰게 한 이름을 써 달라고 한다. 고른 줄의 이름으로 1부터 다시 한다 |
   | `STARTED`                        | 3으로 간다                                                                                                                                                                                                                                                                                                                                     |

3. `NODE_` 로 시작하는 줄과 `FONTS_SKIPPED` 줄을 본다. 없으면 할 일이 없다.
   - `NODE_OK`, `NODE_INSTALLED`, `NODE_SKIPPED`: 할 일이 없다.
   - `NODE_MISSING`, `NODE_DOWNLOAD_FAILED`, `NODE_CHECKSUM_FAILED`: Node.js 24 LTS 를 깐다(22.23.4 이상이어야 1권 2부의 Astro 가 돈다). Windows 면 `winget install OpenJS.NodeJS.LTS` 를 먼저 해 본다. 무엇을 하는지 한 줄로 알리고 한다.
   - `FONTS_SKIPPED`(Windows): 이 폴더의 `글꼴` 폴더에 든 글꼴 파일을 하나씩 열어 **설치**를 누르게 한 줄로 알린다. 직접 설치하지 않는다.
4. `GIT_` 로 시작하는 줄을 본다(3권). 없으면 5로 간다.
   - `GIT_INSTALLING`, `GIT_MISSING`: 둘째 칸의 문장을 그대로 학습자에게 전하고 끝낸다. 저장소 준비는 git 이 있어야 해서 아직 하지 않았다. 다른 일은 하지 않는다.
   - `GIT_OK`: 6으로 간다. `GH_MISSING` 이면 GitHub CLI 를 직접 깔지 않는다. 1-1 3절에서 클코가 다시 챙긴다.
5. 학습자에게 끝났다고 짧게 알린다. 해요체로, 세 줄 안에. 해당하는 줄만 쓴다.
   - 프로그램: 3의 `NODE_` 줄이 있을 때만 쓴다. `NODE_INSTALLED` 이거나 3에서 직접 깔았으면 「Node.js 를 설치했어요」. `NODE_OK`·`NODE_SKIPPED` 면 깐 것이 없으니 「필요한 프로그램은 이미 있었어요」. `NODE_OK` 뒤의 버전과 경로는 이미 있던 Node.js 의 것이다.
   - 재료: `SAMPLES_COPIED` 줄(넣은 수, 넣은 곳)로 정한다. 넣은 곳이 `samples` 면 「연습 재료를 samples 폴더에 넣었어요」, `top` 이면 「연습 파일을 이 폴더에 넣었어요」. 넣은 수가 0 이면 「연습 재료는 이미 있었어요」. 줄이 없으면 쓰지 않는다.
   - 글꼴: `FONTS_INSTALLED` 줄이 있으면 「장표에 쓰는 글꼴을 설치했어요」. 넣은 수가 0 이면 「글꼴은 이미 있었어요」.
   - 지난 버전: `OLD_VERSIONS_COPIED` 줄이 있으면 「지난 버전 폴더에 예전에 저장해 둔 페이지를 넣었어요」. 넣은 수가 0 이면 「지난 버전은 이미 있었어요」. `OLD_VERSIONS_FAILED` 줄이 있으면 그 다음 줄의 문장을 그대로 전한다. 그 밖의 일은 하지 않는다.
   - 폴더: `REGISTERED` 줄이 있으면 「이 폴더에서 이어서 해요」. 경로는 적지 않는다.
   - 다음: 「학습지로 돌아가 다음 단계를 이어서 해요.」
   - 구매: `UNPAID` 줄이 있으면 그 다음 줄의 문장을 맨 앞에 그대로 쓴다. 학습지 서버가 구매를 확인하지 못해 목록을 받지 못한 것이다.
6. 3권은 첫 줄에 「준비를 마쳤어요.」 를 쓰고, 그 아래에 해 둔 일을 목록으로 쓴다. 해요체로, 해당하는 줄만 쓴다. 경로와 신호는 적지 않는다.
   - 프로그램: `GH_INSTALLED` 면 「저장 프로그램 git 과 GitHub CLI 를 준비했어요」, `GH_OK` 면 「저장 프로그램 git 과 GitHub CLI 는 이미 있었어요」, `GH_MISSING` 이면 「저장 프로그램 git 은 이미 있었어요」.
   - `REPO_CREATED`: 「이 폴더를 git 으로 저장할 수 있게 만들었어요」
   - `IGNORE_ADDED`: 「올리면 안 되는 파일은 저장에서 빼 두었어요. 비밀 키를 적어 두는 .env 파일, 맥이 만드는 .DS_Store, 프로그램이 내려받은 node_modules 폴더예요」
   - `RULE_ADDED 1`: 「작업을 마칠 때마다 저장하라는 규칙을 CLAUDE.md 에 적었어요」
   - `SAVED 1`: 「지금 폴더의 모습을 「첫 저장」으로 저장했어요」. `SAVED 0` 이면 「이 폴더는 이미 저장한 적이 있어요」. `SAVE_FAILED` 면 「첫 저장은 하지 못했어요. 다음 작업을 마칠 때 클코가 저장해요」.
   - 재료: 5의 재료 줄과 같다. 3권 2부 샘플(사주풀이·실거래가)은 「연습 파일」 대신 「샘플 화면」 이라고 쓴다.
   - 목록 뒤에 「학습지로 돌아가 다음 단계를 이어서 해요.」 를 쓴다. 7을 하면 그 뒤에 쓴다.
7. `SAMPLES_UNSAVED` 줄이 있으면(3권 2부 샘플을 이미 저장한 적이 있는 폴더에 넣었다) 넣은 샘플을 저장한다. 6의 목록을 쓰기 전에 한다.
   - `pr`: CLAUDE.md 의 저장·PR 규칙대로 한다. 브랜치 이름은 `sample`, 저장 메시지와 PR 제목은 「샘플 화면을 넣는다」다. PR 설명은 양식을 채우고, 무엇이 들어왔는지(화면, 계산·자료 파일, CLAUDE.md 에 더한 안내)를 쓴다. 머지는 하지 않는다. 6의 목록에 「샘플 화면을 PR 로 올렸어요. PR 에서 무엇이 들어왔는지 확인하고 머지해요」 와 PR 주소를 더한다.
   - `save`: 지금 브랜치에 「샘플 화면을 넣는다」로 저장만 한다. 6의 목록에 「샘플 화면을 저장했어요」를 더한다.
8. 실거래가(`STARTED` 둘째 칸이 `budongsan`)는 7 다음에 학습자 폰에서 앱을 열 수 있게 한다. 원고 2-1 3절이 「클코가 보여 준 QR 코드」를 폰 카메라로 찍게 한다.
   1. 이 폴더에서 `npm install` 을 하고, `npx expo start` 를 백그라운드로 띄운다.
   2. 출력에서 `exp://` 로 시작하는 주소를 찾는다. `npx --yes qrcode -o "$TMPDIR/expo-qr.png" <주소>` 로 QR 그림을 만들어 연다(맥 `open`, Windows `start`). 그림 파일은 이 폴더에 두지 않는다.
   3. 「폰에서 Expo Go 를 설치하고, 열린 QR 코드를 폰 카메라로 찍어요. 폰과 이 컴퓨터가 같은 와이파이에 있어야 열려요」라고 알린다. 학습자가 열리지 않는다고 하면 띄운 것을 끄고 `npx expo start --tunnel` 로 다시 띄워 새 주소로 QR 을 만든다.

## 하지 않는 것

- 출력에 없는 파일을 만들거나 고치지 않는다. CLAUDE.md, index.html, references, drafts, plans, .claude 폴더 같은 것은 학습자가 학습지를 따라 직접 만든다.
- 넣은 연습 파일을 열어 보거나 설명하지 않는다. 학습지가 학습자에게 직접 살펴보게 한다.
- `.workbook-tutor` 폴더를 열어 보거나 설명하지 않는다.
- 학습지의 뒤 내용을 미리 알려 주지 않는다.
